# How to Take Smart Notes

> Seed example — a resource note with its matching **Source Catalog** row in [[03_Resources/RESOURCE-INDEX]] (Operational Protocol 5: every source gets a row, even without a note).
>
> It is also the **evidence anchor** for the semantic seed: `[[02_Areas/Example_Area/Example Topic]]` cites this note by its `id`, for both an accepted relation (`knowledge.sources`) and a proposed claim (`knowledge.claim_sources`). See `.agent/knowledge/README.md`.
>
> Note what happened to this note's frontmatter when it became semantic. It previously used `type: book` and `status: reading` — ordinary Obsidian conventions, and both are values the runtime rejects. `type` and `status` now carry schema values, and the original meanings moved to `resource_type` and `reading_status` rather than being discarded. That is the migration this collision forces on any existing vault, and doing it by overwrite loses information.

Ahrens' walkthrough of the Zettelkasten method — the system this vault's linking conventions descend from. Core claim: writing notes *in your own words* and *linking them densely* beats collecting highlights.
